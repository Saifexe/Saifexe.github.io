<Section num="01" title="The challenge">
The original app ran on Supabase with no tests, no containers and no delivery process. Any change went live by hand, and nothing checked it for bugs, leaked secrets or vulnerable dependencies.

My goal: **every commit on main should become a tested, scanned, traceable release, or be stopped with a clear reason.** And I had to do it on free tiers, with 400 CI minutes a month.
</Section>

<Section num="02" title="Architecture">
I rebuilt the backend in Spring Boot with MySQL, JWT authentication and Flyway migrations, kept the React frontend behind nginx, and added a monitoring stack next to the app.

<Figure src={architecture} alt="Ktebna runtime architecture diagram" cap="Runtime architecture: nginx serving React, Spring Boot API, MySQL, and the Prometheus, Grafana and Alertmanager stack" note="Runtime architecture. Ports bind to 127.0.0.1 only; Prometheus scrapes every 15 s and Alertmanager emails the operator." />
</Section>

<Section num="03" title="The pipeline">
Six stages, twelve jobs. Images are built as artifacts but **not pushed** until their own Trivy scan passes, so what reaches the registry is exactly what was scanned.

<Figure src={pipeline} alt="Pipeline stage diagram" cap="The 6-stage GitLab pipeline with nightly rescans of published images" note="Each stage only runs once every blocking job before it has passed." />
</Section>

<Section num="04" title="Key decisions">
<Decisions>
  <Decision title="Scan the artifact, then publish it" why="no gap between what's tested and what ships">Build images, save them as job artifacts, scan them, and push only the scanned image tagged with the commit SHA.</Decision>
  <Decision title="Only main publishes" why="a side branch can't skip the gate">The blocking SonarCloud gate runs on main, so only main can replace the `:latest` image.</Decision>
  <Decision title="Nightly rescans" why="clean yesterday isn't clean today">A schedule rescans published images every night, because new CVEs appear even when the code doesn't change.</Decision>
  <Decision title="Gitleaks on full history" why="a deleted secret is still in git">Secrets are scanned in the working tree and across every past commit, not just the latest diff.</Decision>
  <Decision title="Spend CI minutes wisely" why="400 free minutes a month">Docs-only commits start no pipeline, and older pipelines are cancelled when a newer commit arrives.</Decision>
  <Decision title="Real database in tests" why="catch the bugs production would hit">Backend tests run against MySQL 8 through Testcontainers on Docker-in-Docker, not an in-memory fake.</Decision>
</Decisions>
</Section>

Security isn't one tool. Each layer limits what a failure in another layer can expose.

<Section num="06" title="Kubernetes">
The stack runs in its own namespace with one Deployment and Service per component, PVCs for the database and uploads, and Secrets for credentials. Every pod runs without a service-account token, with CPU and memory limits, and images tagged by commit.

<Figure src={k8s} alt="Kubernetes structure" cap="Kubernetes structure of the ktebna namespace" />
</Section>

<Section num="07" title="Problems I solved">
<Bug symptom="SonarCloud returned 403 in CI even with a valid token." label="Root cause">main was not a protected branch, so GitLab withheld protected variables like `SONAR_TOKEN`. I proved it by checking `CI_COMMIT_REF_PROTECTED` and comparing variable lengths without printing secrets.</Bug>
<Bug symptom="Pods stuck in ImagePullBackOff with 401 Unauthorized.">Images live in a private GitLab registry. I created a read-only deploy token, a docker-registry Secret and `imagePullSecrets`, then cleaned up duplicate ReplicaSets left by the failed rollout.</Bug>
<Bug symptom="Docker-in-Docker builds couldn't reach the daemon.">Configured the DinD service without TLS inside the isolated job and pointed `DOCKER_HOST` at it; passed registry credentials to Trivy explicitly.</Bug>
<Bug symptom="Trivy dependency scans failed on Maven registry rate limits.">Ran the filesystem scan with `--offline-scan` and overrode scanner image entrypoints so they run as CI jobs.</Bug>
<Bug kind="Incident" symptom="A root .env file was staged for the first push, and tokens were later exposed while debugging." label="Response">Removed the file before it reached the remote, rotated the exposed tokens, and recorded the incident and rotation history in SECURITY.md.</Bug>
</Section>
