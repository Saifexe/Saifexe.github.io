<Section num="01" title="The problem">
Server-based internal tools carry hidden costs: patching, capacity planning, paying for idle machines, and environments built by hand in a console that nobody can reproduce.

The question we answered: **can an enterprise app with role-based access, encryption and continuous delivery run on AWS without a single server to manage?**

<Section num="03" title="My part">
**Infrastructure:** wrote the Terraform for Lambda, API Gateway, the four DynamoDB tables with their indexes, KMS keys and IAM roles, so the whole environment can be rebuilt from Git.

**Backend:** built the Python Lambda that handles every route (auth, leave requests and approvals, user admin, leave policies) through internal dispatch on method and path.

**CI/CD:** set up GitHub Actions with separate workflows for the frontend and the infrastructure, plus branch protection and pull-request reviews so nothing reached main unchecked.
</Section>

<Section num="04" title="Key decisions">
<Decisions>
  <Decision title="One Lambda, internal routing" why="one deploy unit, fewer cold starts">A single stateless function routes on HTTP method and path, with all state in DynamoDB.</Decision>
  <Decision title="Pay-per-request tables" why="no idle cost, no table scans">DynamoDB on on-demand billing, with indexes on email and employee_id.</Decision>
  <Decision title="Sessions that expire themselves" why="no cleanup job to run">Tokens live in a Sessions table with a TTL, so DynamoDB deletes them after 30 days.</Decision>
  <Decision title="Encryption and least privilege" why="limit the blast radius">KMS encryption at rest with key rotation; the Lambda role can only touch the tables it needs. Passwords hashed with bcrypt.</Decision>
</Decisions>
</Section>
